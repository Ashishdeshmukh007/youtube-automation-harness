# tts-narration

The voiceover is generated by `studio/tts.py` (MiniMax `speech-2.8-hd`) inside
`python -m studio.pipeline render`. You don't call the API by hand; you control the
*settings* and the *input text*.

## Settings that matter

- **Voice** — pinned via `MINIMAX_VOICE_ID` in `.env` so every episode sounds like the
  same person. Choose a deep, calm, unhurried voice; record the chosen ID in the
  brand-bible. Changing it mid-channel breaks continuity.
- **Pace** — slow. Default speed ~0.92 (set in `providers/minimax.py`). Contemplative
  writing needs room; faster reads sound like an ad.
- **Format** — wav, 44.1kHz mono (already configured). Don't change without reason.

## Preparing the text

- Only the **plain narration lines** of `script.md` are read; `Shot:` lines are
  skipped by the engine. Keep narration clean prose.
- Read the script aloud first. Flag run-ons, tongue-twisters, and unglossed Sanskrit
  to the scriptwriter *before* synthesizing — fixing words is cheaper than re-rendering.
- Spell out anything the model would mispronounce; add a comma where you want a breath.

## Discipline

- Only synthesize an **approved** script (the render gate enforces this).
- MiniMax quota is **shared** across voice/image/music; the engine logs character
  usage into `state.json` under `usage`. Surface it if it grows large.
- Listen to the result. If pacing or a pronunciation is off, adjust and regenerate —
  don't ship a take you wouldn't listen to.
